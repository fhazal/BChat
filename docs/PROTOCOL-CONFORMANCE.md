## Findings (deviations kept as strict xfail tests)

- **FINDING-01**: CASEMAPPING from ISUPPORT is ignored. BChat always folds nicks and channel names rfc1459-style ([]\~ = {}|^). On a CASEMAPPING=ascii server two different users like 'a[b' and 'a{b' become one entry in the nick list. Present since the first version.
- **FINDING-02**: Friends tracking (start_friends) runs right after 001, but the server's 005 (ISUPPORT) with MONITOR/WATCH always comes after 001. So at connect BChat always polls with ISON, also on servers that offer MONITOR or WATCH (e.g. UnrealIRCd). MONITOR/WATCH only start when the friends list changes while connected. The existing friends tests start tracking after connecting, so they did not catch it. Affects the 0.6.0 batch C WATCH fallback. FIXED 11-11 (0.6.0-TEST3): tracking now starts at end of MOTD (376/422), or 5 s after 001.
